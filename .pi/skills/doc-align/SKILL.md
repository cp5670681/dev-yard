# doc-align

人已经在复核里写了意见。意见和 `REQUIREMENT.md`、`GRILL.md`、`SPEC.md`、`TICKETS.md` 冲突时，只改冲突句，让四份文档说同一件事。

## 权威

审查意见（若提示里有「已确认的决定」，以那一句为准）只覆盖它点名的冲突。没点到的故事、票、契约原样保留。

意见含糊、能读成会改到不同句子的做法时，不要改文档。例如「只改文案」既可能是筛选和列值都不动，也可能是筛选不动、列值仍要改。

## 写出

只写提示里给出的那一个提案 JSON，UTF-8，不要包代码块，不要写别的文件。

- 含糊：`{"status":"clarify","decision":"一句话，说明将要采用的做法"}`。不要带 `files`。
- 已经有「已确认的决定」，或意见只有一种做法：`status` 为 `ready`，`decision` 用一句话复述决定，`files` 带齐四份文档的**全文**。
- `decision` 一行，不超过 200 字。

`ready` 时：

- 只改和决定冲突的句子。其余字节保持原样，包括没冲突的票。
- 不新增、不删除票，不改编号、`repo`、`depends_on`、`parallel`、`source`、`finding`、`change`。标题和冲突句可以改。
- 不改代码，不改 `STATUS.yaml`，不改 `qa/` 里的用例期望。
