# resolve-merge（dev-yard）

提测时，宿主把需求冻结分支 merge 进该仓的共享测试分支，遇到冲突就停下来让你解决。**cwd 是冲突现场**（`.yard-worktrees/<JIRA>/<alias>/_test-merge`），只在这个 worktree 里工作。

## 目标

把**本需求的改动**并入测试分支，同时**保留测试分支上已有的、与本需求无关的其它修复**。测试分支是长命共享分支，可能承载别的需求的成果。

## 必读

- `reqs/<JIRA>/REQUIREMENT.md`（产品事实来源）、`SPEC.md`（实现契约）、`TICKETS.md`（只读）
- 启动提示里的冲突文件清单与 conflict 段落摘录
- 启动提示里的冻结分支提交标题（说明本需求带来了什么）

## 做法

1. 逐个查看冲突文件，理解两侧各自改了什么：`<<<<<<<`（测试分支既有）与 `>>>>>>>`（本需求）。
2. 同语义冲突：写能**同时满足两侧**的合并写法，而不是整段取舍。
3. 测试分支与本需求无关的既有修复/行为/测试：**必须保留**，不得为通过而删除。
4. 不得引入与本需求无关的新功能，也不得顺手重排/格式化无关代码。
5. 解决后 `git add -A`；宿主会校验无残留冲突标记并提交 merge commit（若你已自行提交也可以）。
6. 按启动提示的 TDD 文案收尾：
   - TDD 开启：按仓库既有约定跑受影响的测试套件，保持**绿**。
   - TDD 关闭：只做静态检查（语法/明显断链），不写不跑测试。

## 不要

- 不要 push；不要动别的仓或 `reqs/` 下的文档。
- 不要把带 `<<<<<<<` / `=======` / `>>>>>>>` 标记的内容留在文件里。

## 命令安全

所有搜索（`find`/`grep`，含内置工具）限定在当前 worktree，绝不传 `/`，优先 `rg`；`bash` 调用带 `timeout`（跑测试 ≥300s）；别遍历 `/mnt/*`、`/usr/lib/wsl/*`（WSL 的 9p 挂载会阻塞）。详见 AGENTS.md「命令安全」。
